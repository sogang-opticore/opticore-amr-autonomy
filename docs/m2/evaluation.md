# M2 평가 규약

## 임무와 판정 단위

주 지표는 사전 지정 시간 내 **접촉 없는 임무 완료율**이다. M2 manifest에서 각 임무는 한 번의 station-to-station 이동이다. 한 시나리오의 여러 seed/반복을 서로 다른 창고 구조로 세지 않는다. 후속 단계에서 여러 구간을 이은 임무는 모든 필수 구간을 통과해야 성공이다.

| 시행 결과 | 처리 |
|---|---|
| 목표 도착, 목표 식별·좌표와 접촉 관측 유효 | 성공. 운송시간, 이동거리, 개입 횟수를 보관 |
| 장애물과 접촉 | 실패. 정지 상태에서 피격된 경우도 포함 |
| 제한시간 내 미도착 | 실패. 경로 미생성, 회피 중 정체, 차단 해제 후 미재출발 등은 로그로 구분 |
| 센서·TF·접촉 스트림의 검증 실패, 실행기 중단 | 불확실/측정 불능으로 별도 집계. 접촉 0이나 정상 완료로 입력하지 않는다 |
| 실행환경 미기동 | 시작 시도와 사유만 기록. 주행 시행 수와 분리 |

정상 종료가 가능한 시행에서만 보호된 시험 분할을 개봉한다. 개발 단계에는 train 조건으로 준비·실패 재현·계측을 검증한다. 모델 선택은 selection에서 하고, 채택 결정은 선정 시점까지 결과를 보지 않은 test에서 한다.

## 단일 로봇 개발 기준선

접촉 보정 시험(자유공간, 랙 접촉, 정지 로봇에 접근하는 장애물)을 먼저 수행한다. 각 개발 조건에서 새 세계·동일 시작·목표·장애물 시간을 사용한다. 초기 진단 순서는 다음과 같다.

1. 네 가지 train 조건을 B0와 B1에서 각각 실행한다. 첫 반복은 B0→B1, 다음은 B1→B0로 순서를 바꾼다. 초기 진단의 2회당 총 16회 실행은 계측 점검용이다. 이것으로 최종 성능을 추정하지 않는다.
2. 실행 도중 목표, 초기 위치, 경로·상태, 양쪽의 명령, 접촉과 시간 축을 확인한다. 움직이는 장애물의 실제 궤적과 목표 도착 위치도 기록한다. 같은 반복 번호라도 시뮬레이터 내부 잡음과 스케줄링의 동일성은 별도 확인한다.
3. 재현된 대표 실패에는 원본 로그와 원인 분류를 연결한다. 위치추정·지도·A*·목표 입력·실행 지연 문제를 먼저 진단한다. 실제 주행기에서 재현된 문제가 없으면 과거 Lite 실패를 대입하지 말고 실험 질문을 재검토한다.
4. 집계에서 유효·불확실·인프라 실패·누락 수를 함께 제시한다. 측정 불능 시행을 전부 실패 또는 성공으로 가정한 범위도 확인한다. 측정 누락에 따라 결론이 바뀌면 근거 부족으로 판정한다.

## 성능 기준과 예산을 확정하는 방법

- 개발 시점의 실용 개선 폭 후보는 어려운 동적 임무의 완료율 +5%p다. 기존 주행기 성공률이 이미 높으면 양쪽 모두 성공한 같은 임무의 시간 10% 절감을 후보로 둔다. 주 지표와 회귀 허용 폭은 B0/B1 측정 뒤, 후보 정책 평가 전에 한 번 고정한다. 안전성은 접촉 수/율, 정적 회귀는 완료율과 timeout으로 별도 보고한다.
- 짝 비교 키는 임무 ID, 반복 번호와 동일한 환경·구성이다. 이진 지표는 짝 차이와 95% 구간, 성공한 쌍의 시간은 쌍별 차이 또는 비율을 제시한다. 지도를 재사용한 동일 경로의 반복은 같은 조건 안에 묶고, 시나리오 수가 적을 때는 각 조건의 원자료와 불일치 쌍 수를 함께 보인다.
- 개발 pilot에서 두 주행기의 성공 여부가 다른 쌍의 비율과 쌍별 시간 분산을 추정한다. 후보 표본 수로 mission 단위 재표집을 반복하고 주 지표의 95% 구간 폭, 기대 개선 검출력과 실행 비용을 함께 검토한다. 표본이 부족하거나 조건 다양성이 낮으면 추정 폭과 남은 제약을 기록한다. 최종 시험을 보기 전에 시나리오별 표본 수, 포함 기준, 주 지표와 안전/정적 회귀 허용 폭을 동결한다.
- Lite 단일 워커에서 Rule 추론·환경 step·reset을 포함한 24,576스텝을 측정했다. 정적 창고 1,415스텝/s, 동적 창고 1,031스텝/s로 10만 스텝당 약 1.18분과 1.62분이다. [설정과 원시 측정값](../../experiments/m2/lite-throughput.json)
- Gazebo 예산은 새 세계 기동·위치추정 준비 시간에 시뮬레이션 임무 시간/관측 RTF 및 기록 종료 시간을 더해 산정한다. PPO 예산에는 정책 추론·경사 업데이트·검증·checkpoint 시간을 포함한다. 두 비용 모두 해당 환경에서 측정하기 전에는 미확정이다.
