# M2 · 창고 주행 문제 정의와 평가 기반

같은 단일 로봇·창고·시간 제한에서 기존 hybrid 주행기가 어떤 임무를 수행하고 어디서 정체하거나 접촉하는지 측정한다. 기준선은 `opticore-amr`의 실제 위치추정·A*·local control·Gazebo 조합이다. Lite는 준비 비용과 환경 차이를 진단하는 데 사용한다.

## 범위와 인수 조건

| 확인할 것 | 다음 단계로 넘길 증거 |
|---|---|
| 창고와 로봇 | 지도·세계·센서 좌표, 차체와 footprint, 동역학과 지연의 설정/실측 구분 |
| 실제 기준선 | 같은 목표·장애물 일정으로 반복 실행한 B0/B1, 실패 재현 및 원인별 원시 기록 |
| 계측 신뢰성 | 목표 교체 시 이전 도착 신호 배제, 좌표 변환, 시간 제한, 실제 접촉과 접촉 데이터 누락을 구분하는 검증 |
| 비교와 학습 경계 | 개발·선정·독립 시험 분할, 고정할 관측·행동·학습 출발 설정, 운용 지표와 측정 예산 |
| 진행 판정 | 실행된 기준선 결과, 대표 문제, 계측 검증 결과가 갖춰지면 M3로 진입 |

우선 단일 로봇, 정적 운송·횡단·정면 접근·일시 차단을 다룬다. 동적 상황에서 재현되지 않은 문제는 가설로 기록한다. 이후 단계에서 정책 학습, 반복 임무 복구, 두 대의 fleet 호환 및 독립 시험으로 범위를 넓힌다. 실물 로봇과 적재·하역은 이번 검증 범위 밖이다.

## M1 보존과 재사용

- M1 이관 기준 `c44806c3fe2d6e12974b327012ed4570901fabe4`, 현재 개발 기반 `d81ccb6e579469cbdf9c22afa18943544fb254b3`. 두 이력에서 `experiments/m1_reproducibility`의 Git tree는 `68fb03585146f8ef5555fc39a527a2cc3849f5f0`이다.
- 보존한 Lite 평가에서 Shield OFF 성공률은 Rule 86.2%, PPO 5-seed best 85.4%다. D1 정면 접근은 PPO가 모두 충돌했다. 이 관측은 창고 재현 실험의 동기다. [M1 결과](../../experiments/m1_reproducibility/RESULTS.md)
- 원래 `opticore-amr/amr_lite_spike` 보관본을 manifest와 바이트 단위로 대조했다. 체크포인트 12개가 일치했다. 확인한 teacher NPZ 6개는 이름이 일치하고 SHA-256이 모두 다르다. 같은 teacher 데이터로 재학습을 재현하려면 manifest에 맞는 사본을 확보해야 한다. [파일별 해시 대조표](../../experiments/m2/m1-asset-audit.json)
- 재검증 명령은 `python3 scripts/m2/audit_m1_assets.py /path/to/opticore-amr/amr_lite_spike`다. 파일 누락이나 해시 불일치가 있으면 개별 결과를 출력하고 종료 코드 1을 반환한다. M1 모델·데이터·요약 CSV는 보존하며 M2의 기준선 시행 수에는 포함하지 않는다.

## 구현과 실행 증거

**M2 완료.** 2026-11-23 KST 로컬 Docker의 Humble·Fortress에서 개발 임무 4종을 B0·B1로 두 번씩 측정했다. 새 세계 16개에서 16개 유효 종료 행을 확보했다. B0는 2/8 도착, 2/8 충돌, 4/8 시간 초과, B1은 1/8 도착, 2/8 충돌, 5/8 시간 초과였다. [시행별 결과·해시·실측 시각](../../experiments/m2/local-pilot.json)

| 개발 조건 | 반복 0 · B0 | 반복 0 · B1 | 반복 1 · B0 | 반복 1 · B1 |
|---|---|---|---|---|
| 정적 운송 | 시간 초과 120.000 | 시간 초과 120.000 | 무충돌 도착 36.856 | 무충돌 도착 37.416 |
| 횡단 | 무충돌 도착 58.484 | 시간 초과 120.000 | 시간 초과 120.000 | 시간 초과 120.000 |
| 정면 접근 | 충돌 15.504 | 충돌 14.772 | 충돌 14.868 | 충돌 15.356 |
| 일시 차단 | 시간 초과 120.000 | 시간 초과 120.000 | 시간 초과 120.000 | 시간 초과 120.000 |

시간 단위는 목표 발행부터 종료까지의 시뮬레이션 초다. 반복 0은 B0→B1, 반복 1은 B1→B0 순으로 실행했다. 계측 불명·인프라 오류·누락은 정식 파일럿에서 각각 0건이다. 별도로 실행한 기동 실패 재현 및 정적 확인 주행은 이 표의 분모에서 제외했다.

### 재현된 주행 문제

- **정면 접근** 4회 모두 14.772–15.504초에 로봇과 이동 장애물이 접촉했다. 접촉 플러그인의 모델 쌍은 각 시행에서 `amr1`과 `m2_mission_obstacle`이었다. 시간에 따른 장애물 위치는 `actor.jsonl`, 접촉 쌍과 누적 카운터는 `episodes.events.jsonl`에서 대조할 수 있다.
- **목표 근처 정지** 정적·횡단 중 5회에서 DWA가 도착 상태를 냈고 기록기는 120초에 시간 초과를 판정했다. 최종 map 오차가 0.443–0.468 m였다. DWA는 저속에서 경로 끝점까지 0.43 m를 허용한다. 기록기는 최근 map 위치가 지정된 목표의 0.40 m 이내일 때 도착으로 인정한다. 두 판정이 갈린 대표 시행은 `train-static-b0-0`이다.
- **일시 차단** 장애물 제거는 목표 발행 후 20.172–20.280초에 관측됐다. 이후 로봇이 실제로 이동한 거리는 11.69–23.91 m였다. 통로 중심선에서 최대 4.60–7.15 m 벗어났고, 종료 시 목표까지 7.13–16.04 m가 남았다. 네 번 모두 제어기에 복구와 벽 근접 정지 상태가 기록됐다.

### 계측과 재현

정식 실행의 소스는 `661ebc815d3a`, 원본 로봇 스택은 `e8c9197ac280`이다. 컨테이너 안에서 Git SHA와 실행 스크립트의 해시를 확인한 뒤 빌드했고 접촉 CTest 2/2가 통과했다. 16개 시행에서 같은 설치물 해시, 독립 실행 ID, 유일한 goal, 원시 토픽, 접촉 범위, 유효 파라미터 파일의 SHA-256을 확인했다. A*와 AMCL의 유효 파라미터는 양쪽이 일치했다. DWA 파라미터의 차이는 명령 발행 토픽 하나였다. 개발·선정·독립 시험의 기존 분할을 유지했고 개발 조건만 실행했다.

이전 정적 B1에서 관측했던 CLI 종료 코드 1은 기동 직후 `Node not found`로 재현됐다. CLI 데몬의 그래프 탐색을 분리한 통제 재현에서는 미션 준비 확인이 끝난 시점에도 같은 오류가 발생했고, 즉시 `--no-daemon`으로 조회하면 성공했다. 최초 시도의 stderr는 남아 있지 않다. 수정한 기록 경로는 미션 노드가 실제 파라미터 서비스를 직접 호출한다. 정적 B1의 5개 노드, 347개 파라미터를 정상 CLI 덤프와 대조해 시행 ID와 출력 경로 외의 값이 모두 일치함을 확인했다. 수정본의 정상 정적 B1 확인 주행은 37.804초에 무충돌로 도착했다.

별도의 데몬 탐색 장애 시험에서도 기존 CLI가 실패한 같은 시점에 수정본이 다섯 노드의 파라미터를 수집하고 goal을 발행했다. 이 진단 시행에서는 상위 A*가 맵을 받기 0.456초 전에 goal을 무시해 경로 없이 시간 초과됐다. 정식 16회는 모두 목표에 대응하는 경로가 기록됐으며, 이 기동 순서 문제는 정식 시행에서 관찰되지 않았다.
