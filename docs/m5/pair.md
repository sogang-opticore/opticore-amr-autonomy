# M5-R3 · 창고 두 대의 HOLD/RESUME 호환 시험

Humble·Fortress 환경에서 아래 명령은 한 창고에 M4 선정 번들을 탑재한 `amr1`과 `amr2`를 띄운다. 두 목표는 평행한 통로의 개발 좌표를 사용한다. 실행기는 지정한 ROS 도메인을 잠그고 매회 새 Gazebo 파티션을 만든다. 출력 디렉터리는 새 경로를 지정한다.

```sh
python3 experiments/m5/run_pair.py \
  --bundle "$CANDIDATES/7/bundle" --out "$RESULTS/pair-7" --domain 90
```

| 단계 | 통과 조건 |
|---|---|
| 기동 | 로봇별 A*가 지도를 받는다. 독립된 TF와 LiDAR, ground truth, 충돌 계측이 준비되고 두 로봇은 시계 하나를 공유한다. 최종 `cmd_vel`과 `dwa/status`는 각 로봇의 arbiter만 발행한다. |
| 개별 목표 | `amr2`에 먼저 목표를 주면 `amr1`은 미할당·정지를 유지한다. 이어 `amr1`에도 목표를 주면 두 정책이 learned 모드에서 각각 0.12m 이상 이동한다. |
| HOLD | `amr1/goal_pose`에 현재 지도 위치를 새 시각으로 보낸다. `amr1`의 정지 명령·실제 정지를 확인한 뒤 최소 1초간 변위를 0.05m 이내로 유지하고 그동안 `amr2`는 기존 목표를 유지하며 0.12m 이상 이동해야 한다. |
| RESUME | `amr1`에 원래 목적지를 새 시각으로 보낸다. `amr2`의 목표 ID가 유지되는 동안 `amr1`이 learned 모드에서 다시 0.12m 이상 이동해야 한다. |

`run.json`에 시드·지도·번들 해시, 단계별 결과, 발행자·구독자, 정지 시간과 변위를 남긴다. `witness.jsonl`에는 목표와 각 로봇의 정책 상태, 최종 명령, 위치, 충돌 관측이 기록된다. `policies/`에는 로봇별 정책 replay를 보존한다. 물리 충돌, 잘못 수신한 목표, HOLD 중 움직임, 정상 계측 중 시뮬레이션 기한 초과는 `failed`로 기록한다. 계측 단절이나 기동 실패는 `unverified`, 모든 단계 통과는 `verified`로 기록한다.

기본 `pair` 시험에서는 실행기가 upstream fleet의 목표 교체 메시지를 발행한다. 별도 `fleet` 시험은 같은 통로에서 앞차와 뒤차를 1.6m 간격으로 배치하고, upstream `amr_fleet/deadlock_manager.py`를 함께 기동한다. 뒤차의 스캔 수신을 일시 중단해 정체를 유도하고, 실제 관리자가 대기 목표를 보냈는지 DDS 발행자 ID로 확인한다. 스캔 복구 뒤에도 뒤차가 대기하는지, 앞차가 이동하면 관리자가 원래 목적지를 재발행하고 뒤차가 전진하는지 측정한다. 이 장면은 관리자의 대기 시간을 20초로 설정한다. 정면 교행의 후퇴 정책은 별도 시나리오에 해당한다. ## 개발 주행에서 확인한 결과

`ada8aa8`의 개별 제어 시험은 여섯 단계 모두 통과했다. `amr1`이 1.000초 동안 대기한 위치의 변위는 0.000m였고, 같은 시간 `amr2`는 원래 목표를 유지하며 0.379m 이동했다. 이후 `amr1`도 원래 목적지를 새 목표로 받아 재출발했다.

같은 커밋의 fleet 시험에서는 관리자의 대기 목표와 원래 목표 복원을 DDS 발행자 ID로 확인했다. 스캔 복구 후 1초간 후행 로봇의 변위는 0m였고, 최소 간격은 1.600m였다. 관리자가 원래 목표를 평균 0.600초마다 총 34번 재발행하는 동안 후행 로봇은 20초의 재개 기한 안에 0.18m 전진과 `NORMAL` 상태를 함께 달성하지 못했다. 마지막 관측은 `RESUMING`이었고 후행 로봇의 전진 변위는 0.171m였다.

`0da3f11`에서는 운용 모드에서 같은 목적지 좌표가 새 시각으로 재발행될 때 유효한 스캔 이력을 유지한다. 다른 목적지로 교체하면 이력을 비운다. 두 경우 모두 새 목표 ID와 그 시각 이후의 경로를 요구한다.

이 수정을 포함한 `f2e2ee0` 재시험에서는 9단계를 모두 통과했다. 두 로봇의 최소 간격은 1.600m였고, 대기 중 스캔 복구 뒤 1초간 후행 로봇의 변위는 0.001m 미만이었다. 원래 목표 복원 후 전진 변위는 선행 2.769m, 후행 0.253m였다. 실제 관리자의 대기 발행 6건과 재개 발행 7건을 확인했다. 두 로봇 모두 접촉 이벤트가 0건이었다. [시행별 기록](../../experiments/m5/live-development.json)
